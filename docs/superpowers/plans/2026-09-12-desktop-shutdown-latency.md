# Desktop shutdown latency validation

**Goal:** Identify the roughly 90-second quiet interval in Desktop recovery
without weakening filesystem shutdown or shortening timeouts.

**Architecture:** Reuse the frozen `b7510cc3b2a4` kernel, installed Debian,
Stage1 and menu. Compare unchanged shutdown with a runtime-only Bash TERM
trap, then inspect systemd shutdown logs and reduce remaining failures to
diskless signal tests. Repair proven kernel and shell defects separately.
The default menu and installed kernel stay untouched.

**Tech stack:** Existing Python serial transport, C Stage1, Bash, systemd 257.

## Kernel signal repair

- [x] Route systemd console logs to serial in a separate diagnostic menu;
  preserve all images and the default selector. Identify the five processes
  still waiting after TERM, the 90-second SIGKILL escalation, and prompt
  filesystem-detach/reboot after that escalation.
- [x] Reproduce already-stopped SIGCONT behavior with default, ignored,
  caught and blocked dispositions, both process- and thread-directed. Linux
  passes eight cases; the frozen Asterinas image passes two. Keep handlers,
  pending masks and WCONTINUED reporting in the regression assertions.
- [x] Resume at enqueue time in `Process` and `PosixThread`, retaining
  delivery-time default handling. Guard weak process/parent upgrades against
  concurrent exit/reaping as found by ordinary review. Do not claim complete
  pending STOP/CONT cancellation or job-control race repair.
- [x] Run identical strengthened regression archives on both frozen kernels:
  baseline two/eight, repaired eight/eight. Also pass existing kill,
  signal_test2, job_control and rseq userspace tests in QEMU.
- [x] Test the new kernel with the old Stage1 and runtime Bash TERM trap.
  Physical systemd reaches reboot at 3.007 s, first firmware at 6.007 s,
  and the U-Boot prompt at 18.940 s; page JS/DOM/framebuffer checks pass.
