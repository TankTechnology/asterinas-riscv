## 1. 普通用户可重启/关机

Commit: `d2ca05c6e feat(debian): allow console reboot/poweroff without sudo`

- `sudo` 本来就在 `desktop-m4-firefox` / `desktop-m5-network` 的包列表和
  `configure_desktop` 的 sudoers 中（`NOPASSWD: ALL`）；这轮补的是：
  - `polkitd` 加入上述两个 profile 的包列表；
  - 安装
    `/etc/polkit-1/rules.d/49-asterinas-console-power.rules`，允许
    `subject.local && subject.active` 调用 logind 的
    `reboot`/`reboot-multiple-sessions`/`power-off`/
    `power-off-multiple-sessions`。
- 不改内核权限模型；sudo 与 polkit 两条路径可并存。
- **用户可见效果**：新镜像里 `command -v sudo` 有输出，`sudo reboot`/
  `sudo poweroff` 可直接用；即使 sudo 缺失，活动本地会话的
  `systemctl reboot`/`poweroff` 也有 polkit 放行。
- 测试：`test_builder_installs_daily_use_console_for_firefox` 断言
  sudoers、polkit 规则内容/权限；`test_profile_extends_m4...` 断言
  `polkitd` 在 m5 包列表。

## 2. 自毁计时器默认关闭

Commit: `5f5cec3de fix(board): disable self-reboot timers by default`

- 内核 `asterinas.reboot_after` 本来默认 0（`deadline_after_seconds` 对 0
  返回 `None`）；这轮把**工具默认**也关掉：
  `megrez_board_session.DEFAULT_BOOTARGS` 改为
  `loglevel=info init=/init`（不再带 120 s）。
- `megrez_safe_reboot.sh` 把未设置和 `0` 都当作关闭；只有显式正数才
  arm。`asterinas-safe-reboot.service` 不带 `ASTERINAS_SAFE_REBOOT_AFTER`
  环境变量；需要恢复时在 bootargs 里显式写
  `systemd.setenv=ASTERINAS_SAFE_REBOOT_AFTER=<正数>`。
- `docs/porting/megrez-board-session-commands.md` 的示例改为
  `asterinas.reboot_after=0`，并注明默认不自毁。
- **用户可见效果**：正常启动后不会再在 30/60 分钟自动回 eMMC Debian；
  只有显式正数才启用。
- 测试：`test_safe_reboot_defaults_off_and_treats_zero_as_off`（unset/0
  均无动作、退出 0）；board-session 默认 bootargs 断言已更新；
  m5 builder 断言 safe-reboot unit 不含该 env。

## 3. DNS shim / 网络 / desktop-ready 快速失败

Commit: `23dbd4045 fix(debian): fail fast and decouple desktop readiness from network`；watchdog follow-up: `73c690eb1 fix(debian): keep desktop-ready active without a reboot watchdog`

- `asterinas-dns-shim.service`：`Type=oneshot`、`Restart=no`、
  `SuccessExitStatus=1 3`。exit 3（未配置 forwarder）和 exit 1
  （tunnel 不可达）现在是明确的 inactive 状态，不 restart、不算 failed；
  需要重试时显式 `systemctl restart asterinas-dns-shim`。
- `asterinas-desktop-m5-network`：unit `TimeoutStartSec` 180 s → **45 s**；
  evidence 脚本全局 120 s → **30 s**，单命令 30 s → **10 s**；
  browser-web drop-in 600 s → **45 s**。网络不可达不再拖住 boot。
- `physical_graphics_control.sh` 的 `startup-ready`：
  - browser 启动失败只打 `ASTERINAS_DESKTOP_BROWSER_OPTIONAL start=failed`，
    不再把 `__ASTERINAS_PHYSICAL_BROWSER_START__` 置为非零；
  - desktop 就绪判定只要求 debug console、`/dev/fb0`、X socket、Xorg
    fbdev、openbox；**Firefox/网络不再是 desktop-ready 的强依赖**。
  - 自毁计时器默认关闭后内核 watchdog 可能不存在；`startup-ready`
    现在打印 `ASTERINAS_DESKTOP_WATCHDOG_ABSENT` 后继续，不再因
    `watchdog-unavailable` 失败；显式 armed 时仍走原有 disarm 路径。
- **用户可见效果**：无网络时 desktop-ready 仍 active；DNS 未配置时
  `systemctl status asterinas-dns-shim` 是 inactive 而不是无限重启/失败；
  网络失败约 45 s 内结束。预期新镜像 `systemctl --failed` 为
  **2**（`asterinas-desktop-m5-network` + `systemd-random-seed`），
  从 5 降到 ≤2；`systemd-random-seed` 不在本轮范围。
- 测试：dns unit 的 oneshot/`Restart=no`/`SuccessExitStatus=1 3` 源断言；
  network deadline 30 s 和 unit 45 s 的断言；desktop-ready 的
  Firefox-optional 源断言；browser-web drop-in 45 s 断言。

## 4. 板钟不再落在 2026-04-13

Commit: `31021f025 fix(debian): seed the guest clock from the image build time`

- 新增 `megrez_clock_bootstrap.sh` 和
  `asterinas-clock-bootstrap.service`（basic.target, oneshot）；
  镜像里写 `/etc/asterinas-build-time = $SOURCE_DATE_EPOCH`。
- 启动时若当前时间早于构建时间或比构建时间晚超过一年，就设为构建时间；
  否则保留（避免和正确 RTC/NTP 打架）。输出
  `ASTERINAS_CLOCK_BUILD_TIME_APPLIED/SKIPPED/MISSING/INVALID`。
- **用户可见效果**：新镜像 `date` 不再显示 2026-04-13；默认使用
  `SOURCE_DATE_EPOCH`（当前 builder 默认 2024-01-01，实际构建建议
  `SOURCE_DATE_EPOCH=$(date +%s)`），在线 `megrez-clock-sync` 之后仍可
  用代理 Date 覆盖。
- 测试：`test_megrez_clock_bootstrap` 三个用例（远未来时间被替换、
  合理时间保留、缺文件明确报告）；daily-use builder 断言 build-time 文件、
  unit、脚本和 basic.target.wants 链接。
