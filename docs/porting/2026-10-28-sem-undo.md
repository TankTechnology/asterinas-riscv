# System V 信号量 SEM_UNDO（P5）

日期：2026-10-28
基线：`origin/main`（`148b2db64`）

## 1. 现状与目标

`SEM_UNDO` 以前被直接拒绝：

```rust
if flags.contains(IpcFlags::SEM_UNDO) {
    // TODO: Add support for the `SEM_UNDO` flag
    return_errno_with_message!(Errno::EINVAL, "SEM_UNDO is not supported yet");
}
```

带 `SEM_UNDO` 的 `semop(2)` 是很多数据库/构建脚本用来「进程死了就把锁还回去」
的手段；直接 `EINVAL` 会让这些程序在启动阶段失败。目标是按 Linux 语义实现：
进程退出时自动回滚它做过的、带 `SEM_UNDO` 的调整。

## 2. 实现

| 位置 | 改动 |
|---|---|
| `kernel/src/ipc/semaphore/system_v/sem_set.rs` | `SemSetInner` 增加 `undo: BTreeMap<Pid, Box<[i32]>>`（每个进程每个信号量的待回滚量）；新增 `SemaphoreSet::apply_undo(pid)` |
| `kernel/src/ipc/semaphore/system_v/sem.rs` | `PendingOp::new` 接受 `SEM_UNDO`；`perform_atomic_semop` 在成功执行后记录 `-sem_op`（按 `SEMAEM` 截断）；`update_pending_alter` / `wake_const_ops` / `do_smart_wakeup_zero` 透传 `undo` |
| `kernel/src/ipc/ipc_ids.rs` | `IpcIds::for_each`，用于遍历一个 IPC 命名空间的所有信号量集 |
| `kernel/src/ipc/ipc_ns.rs` | `IpcNamespace::apply_sem_undo(pid)` |
| `kernel/src/process/posix_thread/exit.rs` | 进程最后一个线程退出、`ns_proxy` 还在时调用 `apply_sem_undo(pid)` |

语义对齐 Linux：

- 记录的是操作的相反数（`+2` 记 `-2`），累计并按 `SEMAEM` 截断；
- 应用时 `semval + semadj` 截断到 `[0, SEMVMX]`，并把 `sempid` 更新为退出进程；
- 应用后运行一次 pending 队列扫描，让因此变得可执行的 `semop` 被唤醒；
- 只在最后一个线程退出时应用（`is_last_thread`），与 Linux 的线程组退出一致；
- 信号量集被删除时 `undo` 随集释放，与 Linux 相同。

## 3. 验证

`tools/x86/debian/semundo_test.c`：父进程把信号量设为 5；子进程 `+2` 带
`SEM_UNDO` 后退出；第二个子进程 `-2` 带 `SEM_UNDO` 后退出；父进程在每次
`waitpid` 后打印当前值。

宿主机 Linux 基线：

```
child_up_sees=7
after_up_exit=5
child_down_sees=3
after_down_exit=5
```

Asterinas（x86_64，`--scheme microvm`，静态二进制作为最小 initramfs 的
`/init`，`-smp 2`）：

```
[     0.248] DEBUG : semop: semid = 1, sops = 0x7ffffff43de0, nsops = 1, timeout = None
child_up_sees=7
after_up_exit=5
[     0.523] DEBUG : semop: semid = 1, sops = 0x7ffffff43de0, nsops = 1, timeout = None
child_down_sees=3
after_down_exit=5
```

与 Linux 完全一致：正向和负向的 `SEM_UNDO` 都在进程退出时回滚，没有越界。

注意：本轮 main 的 `kernel/src` 还不能引导 Debian 镜像（缺可挂载的 devtmpfs 与
`--root-init=systemd` 接续，Stage1 会停在 `DEBIAN_ROOTFS_FAIL
reason=devtmpfs-mount`），所以这个测试用独立 initramfs 直接验证内核路径，不依赖
Debian rootfs。

## 4. 同批清单里的其他项

- **kcmp(312)**：main 已有完整实现（`kernel/src/syscall/kcmp.rs`：
  `KCMP_FILE`、`KCMP_FILES`），无需改动。
- **WNOTHREAD**：`WaitOptions` 接受该标志，但 Asterinas 的子进程天然按进程统计
  （按线程区分的等待语义没有建模），因此「忽略 WNOTHREAD、按进程等待」是
  Linux 的默认行为，属于良性差异；没有为它引入 forking-thread 记录。
- **/proc/stat 的 USER_HZ**（P3）：main 的 `a73b65622`（"Align procfs startup
  statistics with Linux clock units"）已经修好，`proc/stat` 通过
  `jiffies_to_clock_ticks`（100 Hz）输出。运行时复核：2 vCPU 空转 10 s，
  `cpu` 行合计从 44 增至 1995（**1951 ticks ≈ 97.6 ticks/s/CPU**），若是 1000 Hz
  应为约 20000。
