# 叶子层是「存在但几乎全空」：0 页仍走 936 个 PTE/调用

日期：2026-10-26
内核基线：`905bb297a`
本轮：轻量计数仪表（**无逐迭代 rdtsc**）+ 分析；**插桩已 revert**，内核 21:28 重编译为基线字节

## 0. 任务 A 的明确回答

**PTE 层是「存在、且已被下降进去逐项走」，不是「不存在」；现有的空节点跳过从不触发，
因为每个被下降的 PT 里至少有一个存在项。**

证据（0 页窗口，200 次 `madvise` + 200 次 `munmap`，LF1 前后差值）：

```
L1: absent +187,164  pt_nonzero +0    pt_zero +0     ← 叶子层步进 ≈936 次/调用
L2: absent   +4,669  pt_nonzero +417  pt_zero +0     ← 约 1 次/调用下降，且该 PT 有子项
L3: absent   +3,066  pt_nonzero +6    pt_zero +0
L4: absent   +1,524  pt_nonzero +6    pt_zero +0
```

- **`pt_zero` 增量为 0**：`cursor/mod.rs:225-231` 那个「`nr_children()==0` 就跳过整段」的分支
  在这 400 次 unmap 里一次都没命中。
- **`L1 absent` ≈ 936 次/调用**：叶子层是一页一页走过去的，与上一轮 `find_next_impl` 的三段数据
  一致（scan 25.7 % + fetch 35.1 %）。
- 层级下降可以忽略（L3/L4 每调用几次）。

⇒ 任务 B 的两个分支里，**A-scan（叶子层整段跳过）适用，A-level 不适用**。

## 1. 为什么本轮没有落地 B 或 C

1. **B 需要的能力当前 API 没有**：任务书建议「一次读 8 个 PTE 判断全空」或「跳到 PMD 边界」，
   但页表 cursor 只暴露 `cur_entry()` / `move_forward()`，没有 peek-ahead、没有每 PT 的
   present 位图；`next_present()` 只存在于 `xarray::Cursor`，不在这套页表游标上。
   要在叶子层做批量判断，得先给 `PageTable`/`Cursor` 加一个「节点内位置位图/下一个存在项」
   原语——那是结构性改动，不是单变量小改。
2. **C 需要的驻留信息不在 mapping 上**：RSS 只在 **VMAR 级**累计
   （`vm/vmar/vmar_impls/mod.rs:141-175` 的 `RssDelta` / `add_rss_counter`），
   `VmMapping` 只有 `rss_type()`（`vm_mapping.rs:217`）而没有被驻留统计。
   用 VMAR 级 RSS 做判断会误伤（别的 mapping 可能有页），不能当作单变量改动上线。
3. 时间盒：改 cursor 原语 + 编译 + `pthread` 基准 + 7 域矩阵，剩余时间不够安全完成，
   按纪律只交数据。

## 2. 下一轮的具体落点（按可行性排序）

1. **给 PT 节点加 present 位图**（或「下一个存在 PTE」原语）：叶子层扫描时一次跳到下一个存在项，
   把 936 步/调用压到「存在项数 + 1」。这是 Linux 之外常见的做法，改动局限在 page table 内部，
   不破坏 ostd 抽象（新增安全 API）。
2. 或者退一步：在 `find_next_impl` 里，当 `self.level == 1` 且父 PT 的 `nr_children()` 已知时，
   记账「已越过最后一个子项」后直接跳到 PT 边界（需要把 `nr_children` 与子项位置一起带下来）。
3. C 的可行版本：给 `VmMapping` 加**按 mapping 的驻留计数**（在 page fault / unmap 处维护），
   然后 `discard_pages` 遇到 0 驻留的 mapping 直接跳过。这条与 1 独立，可单独验收。

## 3. 仪表说明（本轮方法）

按要求改为**纯计数**：`PageTable` 分支记录层级与 `nr_children()==0/≠0`，
`Absent` 分支记录层级；每层一个 `AtomicUsize`，`/proc/leaf_stats` 一次读出。
没有任何逐迭代 `rdtsc`，避免上一轮仪表自身占 34 % 的问题。
