ELF ≠ booti Image

QEMU 可直接理解 ELF 段；U-Boot booti 读取的是平坦 Image，不能在已经链接好的 raw image 前再插入 64 字节。

RockOS 是跳板

RockOS 用来传输、校验、安装新文件并正常重启；它不是 Asterinas 运行链的一层。

DTB 是数据契约

它描述 CPU、内存、设备和 /chosen。U-Boot 搬运它，Asterinas 解析它，但 DTB 本身不是固件。

NO RECOVERY · NO BOOTI

串口只能有一个所有者；RAM 环境与 DTB /chosen/bootargs 必须逐字一致；禁止 saveenv；每份产物只执行一次 booti。整个观察期都具备外部复位或断电能力，否则停在 U-Boot。

精确 bootargs

cpu_no_boost_1_6ghz loglevel=info init=/init。非空 RAM bootargs 会覆盖 DTB，仅修改 DTB 不够。

传输身份

文件先进入 /tmp/*.part，完成后 rename；哈希一致才以本轮唯一文件名安装到 /boot 并 sync。

命令发送

U-Boot 长命令需要逐字符节流并核对完整回显；回显完整也不等于命令已经完成。

真机已验证边界：PID 1 已进入用户态，第一次 write 返回成功。UART 日志中没有用户态 hello；Asterinas 未接收 framebuffer，因此也没有 HDMI 输出路径。当前首个缺失边界是 console route；它不是 exec 或系统调用阻断。

默认 Sv48

6df0f28f 已在真机越过 Sv48、OSTD、3 AP 和 rootfs。Sv39 只在 satp 拒绝或 marker 指向分页时作为诊断。

A/D 位

QEMU 的 Svade/Svadu 两端用于暴露软件页表假设；它不能证明 EIC7700 真正采用哪种 A/D 行为。

随机源 fallback

缺少 Zkr 与 DTB seed 时，时间戳 fallback 会打印不安全警告但继续启动；这适合 bring-up，不是最终熵方案。

HISTORICAL · NOT A CONSTANT

下一轮必须重新执行 bdinfo。历史地址可解释门禁结构，但不能无条件复制到另一块板、另一版固件或另一份 Image；文件大小变化会改变末端地址。

真机地址

历史模板使用 Image 0x80200000、initramfs 0x83000000、DTB 0xf0000000。

QEMU 不同

通用 QEMU U-Boot 流程的 DTB 地址为 0x88000000；不能把它与真机 0xf0000000 混用。

Image 内部布局

header 位于 +0x0000，boot body +0x0040，Sv48 root +0x1000，Sv39 root +0x3000。

真机已验证边界：PID 1 的 write 返回成功，但 UART 日志中没有用户态 hello；Asterinas 未接收 framebuffer，因此 HDMI 尚无输出路径。同一受控会话随后观察到新的 OpenSBI banner → U-Boot banner → U-Boot prompt。下一阶段只处理显示、控制台路由与输入，不再回退到 PID 1 之前重复排查。

Marker 是边界，不是装饰

每条 marker 都应位于一次不可逆转换前后；没有 marker 指向时，不要一次重写多层启动代码。

WDT0 结论

历史实验确认 counter 递减，但超过 705 秒仍未出现新 banner 或 prompt，因此 WDT0 不能作为恢复保障。

成功 marker

>>> Hello from RISC-V userspace on Asterinas! <<<

完整恢复必须依次看到新的 OpenSBI banner → U-Boot banner → U-Boot prompt；任何不完整序列都不能记为 PASS。

Do not merge these evidence lines

五条证据线，五种边界

这些结论来自不同 Image 与不同运行环境，不得串成同一份 Image 的连续运行。当前 3ef99e6bd 真机证据证明 PID 1 与恢复；它不证明 framebuffer、UART 或输入设备已经可用。

16 GiB direct QEMU slow PASS

7f691c479

QEMU 软件恢复 timer / panic PASS

冻结的默认 Sv48 Image 在 timer 与 panic 场景都通过真实 U-Boot booti 软件恢复；每场景均清理 QEMU、socat 与临时文件，启动盘未被修改，但这不能证明 EIC7700 厂商 SBI reset。

QEMU 已覆盖的软件链路

  • RISC-V Image 布局与通用 booti 软件链路
  • 默认 Sv48、4 HART、Svade/Svadu 两端的软件假设
  • stale RAM bootargs 导致 init ENOENT 的机制
  • 无 Zkr、无 DTB seed 时的 timestamp fallback
