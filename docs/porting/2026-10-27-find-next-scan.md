## 0. 结论（含自证失败）

1. **两段自证（A-level + A-scan ≈ A-total，±15 %）没有通过**：
   0 页窗口 level 0.05 % + scan 25.7 % = 25.8 %，远低于 100 %。
   按纪律「自证不过不许进 B」，**本轮没有改任何扫描策略**，任务 B 未执行。
2. 补测第三段（每次迭代的取项：`cur_va_range()` / `cur_entry()` / `fits_range`）后，
   覆盖到 **66 %**（level 0.05 + scan 25.7 + fetch 35.1），剩余 ~34 % 是循环控制、
   分支派发与**三处 rdtsc 自身的开销**——仪表本身已经不可忽略。
3. 但有一条**与仪表无关、可直接采信**的计数结论：
   **0 页场景下每次 8 MiB `madvise` 仍要扫 ≈970 个 PTE 项**
   （scan_iters 194 070 ÷ 200 次调用）。层级下降只有约 2 次/调用（level_iters 440 ÷ 200）。
   ⇒ 「逐 PTE 步进」确实存在且量级匹配 P3 的 58.9 µs，任务 B 的 A-scan 分支方向是对的。

## 2. 怎么读这些数

- **层级下降不是问题**：`level_iters` 只有 440（≈2 次/调用），耗时占比 0.05 %。
- **叶子扫描是真实存在的成本**：≈970 次 PTE 步进/调用，占 26 % 的 `find_next_impl` 时间；
  每次步进还有一次 fetch（35 %），两者合计约 61 %。
- 剩余 ~34 % 主要是循环/分支开销与 `rdtsc` 自身（每次迭代 3 次 rdtsc，约 60–90 cycles），
  所以**绝对占比会被仪表放大**；但「≈970 步/调用」这个计数不受仪表影响。

⇒ 结论：`find_next_impl` 的开销来自**逐 PTE 走到范围末尾**，而不是从根重复下降。
任务 B 的两个分支里，**A-scan 分支（叶子层整段跳过）适用，A-level 分支不适用**。

## 3. 为什么没进 B

任务书写明「A 自证不过不许进 B」，而 level+scan 只覆盖 33 %（FN1）——自证失败，
说明我选的 A-level/A-scan 划分不足以解释函数耗时。补测 fetch 后覆盖到 66 %，仍不足以通过
±15 % 的自证。按纪律停在这里，没有改 `find_next_impl`，也没有跑矩阵。

**下一轮建议**（数据已足够支撑）：
1. 直接实现「叶子层整段跳过」：当父 PMD 项指向的页表没有子项时一次跳过整段 PTE
   （`cursor/mod.rs:225-231` 的 `nr_children()==0` 分支已存在，需查清为何 0 页场景下
   仍然走了 ≈970 个 PTE——很可能是 mmap 时页表已被铺到 PTE 层，且该 PMD 下有少量子项）；
2. 仪表上把三处 rdtsc 减到一处（进入函数打一次、退出打一次，用迭代计数分摊），
   避免仪表自身成为 34 % 的噪声；
3. 验收仍按 0 页 <30 µs、2048 页 <60 µs，并跑 7 域矩阵。
