# Clock synchronization with systemd-timesyncd, 2026-11-09

The Megrez board has no RTC. Until now the image scraped the campus gateway
for the time in `megrez-clock-sync.py`, run as an `ExecStartPre` of the desktop
service. That only worked on the campus network, only at desktop start, and
left the clock to drift afterwards. The image now uses the standard Debian
client, `systemd-timesyncd`, and the kernel grew the two facilities it needs.

## Why a kernel change

`systemd-timesyncd` starts with `setsockopt(SO_TIMESTAMPNS)`. The kernel used
to accept the option and attach nothing, so the client aborted with
`Packet timestamp missing`. `chrony` instead calls `adjtimex(0x8001)`, which
returned `ENOSYS`.

Two pieces were added:

- **Timestamp cmsgs.** `SO_TIMESTAMP` and `SO_TIMESTAMPNS` are now real socket
  options, and UDP `recvmsg` attaches `SCM_TIMESTAMP` / `SCM_TIMESTAMPNS` to
  the control message. The stamp is taken when the datagram is delivered to
  the caller rather than when it arrived at the device; arrival-time stamping
  belongs in the network stack (smoltcp) and is not needed for millisecond
  accuracy. A sender that supplies these types is ignored on the receive path.
- **`adjtimex(2)` / `clock_adjtime(2)`.** One step-based implementation over
  the asm-generic `struct timex`. Reads (`modes == 0`) fill the current time
  and status; writes require `CAP_SYS_TIME`. `ADJ_SETOFFSET` applies `time`
  verbatim, with `time.tv_usec` treated as nanoseconds when `ADJ_NANO` is set
  (that is what timesyncd sends); `ADJ_OFFSET` steps the clock in the opposite
  direction because it reports local minus reference.

Two ABI traps found on the board:

- riscv64 glibc calls `clock_adjtime` as **266**, not the asm-generic 305.
  The first build wired 305 and every call stayed `ENOSYS`.
- `ADJ_SETOFFSET | ADJ_NANO` carries the fraction in the `time.tv_usec` field,
  but it is in nanoseconds. Multiplying it by 1000 pushed the clock hundreds
  of seconds into the future. The step is now the value as-is.

Frequency discipline (`ADJ_FREQUENCY`, PLL) is still not modelled: offsets are
steps. timesyncd converges with steps, and a later PLL can replace the step
without changing the ABI.

## Image

`browser-m5` now requests `systemd-timesyncd` (and its identity packages). The
build adds `/etc/systemd/timesyncd.conf.d/asterinas.conf` with
`ntp.aliyun.com time.cloudflare.com`, Debian fallback pools, and
`PollIntervalMinSec=16` / `PollIntervalMaxSec=64` — under desktop load the
board clock drifts enough that a five-minute poll is too coarse. The unit is
enabled at `sysinit.target`, not `basic.target`: units with
`DefaultDependencies=no` in `basic.target.wants` never ran on this image.

`/var/lib/systemd/timesync` is pre-created and chowned to `systemd-timesync`,
because Asterinas' systemd fails to create the `StateDirectory` at service
start with "Failed to set up special execution directory in /var/lib:
Invalid argument".

The desktop unit's `megrez-clock-sync` `ExecStartPre` and the script itself
are removed, along with their tests and the runtime digest entry.

The current board image was updated in place (package + config + state dir +
symlink); the build-script changes take effect on the next image build.

## Board validation

Kernel built as `aster-kernel-timesync4.img` and booted once from U-Boot with
`ext4load` / `booti` (the U-Boot prompt was interrupted with repeated `\r`,
then `!RAW` mode toggled in the serial bridge). Test: set the clock 300s ahead
of the host, start timesyncd, wait 75s. The clock landed on the host second
exactly (`1794213951` both sides).

The image was then persisted as the default kernel:

- `/root/kernel-rel.img` — sha256 `dcd125584fc52681ee1cda7e03df5720e8959d3743c98b2642f1c14e4d77d176`
- `/root/kernel-rel.img.bak` — the previous image (`e2d53755...`)

After a normal reboot, `systemd-timesyncd` reported
`Initial clock synchronization to Mon 2026-11-09 08:48:15.868070 UTC`, and the
subsystem selftest ended with:

```
PASS console  clock      epoch=1794214162 delta=8s
SELFTEST total=11 pass=10 fail=0 skip=1 complete=True
```

The remaining 8s is poll phase, not drift: the clock is stepped to the server
value and parks there until the next poll.

## Rollback

Boot the U-Boot prompt and load `/root/kernel-rel.img.bak` with the same
`booti` arguments the `bootcmd` uses, or copy it over `kernel-rel.img` from
the running system. The timesyncd unit can be disabled with
`systemctl disable systemd-timesyncd`; nothing else depends on it.
