# 内存侧收尾：per-mapping 驻留计数已实现且正确，但快路径未生效（负结果 + 待查项）

日期：2026-10-26
内核基线：`a966812e2`
本轮：实现 → 正确性验证通过 → 性能未达预期 → **按纪律 revert**，内核 21:53 重编译为基线字节

## 0. 一句话结论

per-mapping 驻留计数**实现正确**（1000 次随机 mmap/touch/madvise/munmap 后
`mismatches=0`），但接上 `discard_pages` 快路径后**0 页 madvise 仍 78.96 µs（基线 78.60 µs），
完全没有改善**。由于时间盒用尽，无法再定位「快路径为何未触发」并跑完 7 域矩阵，
按纪律把内核改动整体 revert，只留结论与待查项。**内存侧到此为止，不再往下推。**

## 1. 做了什么（已 revert，留档）

1. `VmMapping` 新增 `resident_pages: AtomicUsize`（`vm_mapping.rs`），
   `resident_pages()` / `note_resident_pages(±n)` 两个访问器；
   为适配非 `Copy` 的原子字段，重写了 `new_fork`、`clone_range_for_remap_at`、`split_range`、
   `merge_with` 四处 `..*self` 构造（拆分时两半都继承父计数 = **保守上界**）。
2. 维护点与 VMAR 级 RSS 的增减点一一对应：
   - 增加：缺页装入（`vm_mapping.rs` 两处，紧跟 `rss_delta.add(..., 1)`）
   - 减少：`discard_pages`（`unmap.rs`）与通用 `unmap`（`vmar_impls/mod.rs`），按 `cursor.unmap()` 的返回值扣减
   - `rmap.rs` 的失效路径不持有 mapping 句柄，未改（保守）
3. `discard_pages` 快路径：`resident_pages()==0 ⇒ 跳过该 mapping`（不建 cursor）。
4. **自校验开关** `VERIFY_RESIDENT`：为 `true` 时快路径关闭、照常遍历，
   凡「计数为 0 但仍有页被 unmap」都计入 `RESIDENT_MISMATCHES`，通过临时 `/proc/resident_stats` 暴露。

## 2. 正确性专项（通过）

```
PROBE before=skips=0 mismatches=0
（1000 次随机 mmap 1..64 页 / 随机 touch 2/3 页 / 随机 0..2 次 madvise / munmap）
PROBE after=skips=0 mismatches=0
```

⇒ 在校验模式下，**从未出现「计数器说 0、页表却仍有驻留页」**的情况。
方向安全性是对的：计数只会偏大（漏减）不会偏小（漏加）——偏大只会少触发快路径，不会错误跳过。

## 3. 性能（未达预期）

| 场景 | 基线（SH1） | 快路径版（RS1） |
|---|---|---|
| 0 页 8 MiB madvise | 78.60 µs | **78.96 µs（无变化）** |
| 512 页 | 183.76 µs | 195.54 µs |
| 2048 页 | 692.13 µs | 712.85 µs |

0 页场景**本应**是快路径的理想用例（新映射、零驻留），却没有任何变化。

## 4. 待查项（下一轮从这里开始）

最可能的原因，按嫌疑排序：

1. **`resident_pages() != 0`**：某个未覆盖的路径把计数抬高了——比如 `mmap` 时对 mapping 的
   预置/首页故障，或 `merge_with` 继承计数（我的实现里合并是相加，若反复 merge 会虚高）。
   **验证方法**：在 RS1 的探针里加一行读 `/proc/resident_stats` 看 `skips` 是否为 0
   （本轮探针没读，这是本轮的方法缺陷）。
2. **快路径没被执行到**：`discard_pages` 的 `for vm_mapping in inner.vm_mappings.find(&range)`
   对整段 8 MiB 只应命中 1 个 mapping；若 `find` 返回 0 个，则整段都会被跳过（与观测矛盾，
   因为时间没变，说明仍走了 old path）。
3. 若 1 成立，先修计数来源（很可能只需在 `mmap`/`merge` 处不继承计数），再重测。

**方法论教训**：性能探针必须同时读出**命中计数器**（`skips`），否则无法区分「没触发」与「触发了但没用」。
