# Atomic KMS and sync objects on the x86 line (P3, first block)

Part of milestone P3 in
[`docs/porting/drm-shared-core-design.md`](../../drm-shared-core-design.md).
The shared `aster-drm` core now accepts atomic commits for the minimal
single-CRTC shape, and exposes a sync-object surface. Both are driven through
the same driver plugin as the earlier milestones, so the same probes run on
x86_64 and RISC-V.

## Kernel

### Atomic KMS

- `kernel/comps/drm/src/ioctl/atomic.rs` implements
  `DRM_IOCTL_MODE_ATOMIC` (0xbc), `DRM_IOCTL_MODE_CREATEPROPBLOB` (0xbd) and
  `DRM_IOCTL_MODE_DESTROYPROPBLOB` (0xbe).
- `DRM_CLIENT_CAP_ATOMIC` is now accepted from `DRM_IOCTL_SET_CLIENT_CAP`
  (it previously returned `EOPNOTSUPP`); atomic properties stay hidden from
  clients that have not enabled it.
- The application path is shared with legacy `SETCRTC`: the CRTC/plane/
  connector validation and state publication were extracted from
  `drm_mode_set_crtc` into `DrmFile::commit_modeset`, and both ioctls call it.
  `TEST_ONLY` runs the same validation and stops before the driver hook.
- Supported commit shape: one CRTC (`ACTIVE`, `MODE_ID`), the connectors
  whose `CRTC_ID` routes to it, and its primary plane (`FB_ID`, `CRTC_ID`,
  `SRC_X/Y/W/H` as 16.16 fixed point). A commit with no `MODE_ID`, an
  unknown/immutable property, or a non-primary plane is refused.
- User blobs are tracked per DRM file and released on close, so a client that
  exits without destroying its blobs does not leak object IDs.

### Sync objects

- `kernel/comps/drm/src/syncobj.rs` holds the sync-object state
  (binary signal + timeline point) and the per-file handle table.
  `kernel/comps/drm/src/ioctl/syncobj.rs` implements create/destroy, binary
  signal/reset/wait, timeline signal/wait and query
  (0xbf/0xc0/0xc3/0xc4/0xc5/0xca/0xcb/0xcd).
- `DRM_CAP_SYNCOBJ` (0x13) and `DRM_CAP_SYNCOBJ_TIMELINE` (0x14) report 1:
  the implementation lives in the core, not in a driver.
- Blocking waits use a new public primitive in `aster-core`,
  `aster_core::wait_until_or_timeout(cond, register_waker, timeout)`, over
  `ostd::sync::Waiter`; a second public helper `aster_core::monotonic_now()`
  resolves the UAPI's absolute `CLOCK_MONOTONIC` deadlines. A timeout of zero
  is a non-blocking probe, a negative value is relative, a positive one is
  absolute, as in Linux.
- Waits are not interruptible by signals in this block.

### Vblank

`DRM_IOCTL_WAIT_VBLANK` (0x3a) is a defined placeholder: it consumes the
request and returns `EOPNOTSUPP`. The driver has no refresh interrupt (scanout
is presented by transfer/flush), and a fake sequence number would be worse
than an explicit "unsupported".

## Acceptance

Both probes are architecture-neutral static binaries used as a one-file
initramfs `/init` (`tools/drm/initramfs_probe_check.sh`).

### Atomic KMS (`tools/drm/atomic_probe.c`)

```
ATOMICPROBE_MODE 1024x768
ATOMICPROBE_PLANE 1
ATOMICPROBE_FB 20
ATOMICPROBE_BLOB 21
ATOMICPROBE_CAP ok
ATOMICPROBE_TEST_ONLY ok
ATOMICPROBE_COMMIT mode=1024x768 fb=20
ATOMICPROBE_LEGACY ok
ATOMICPROBE_REJECT_PAGE_FLIP_EVENT ok
ATOMICPROBE_REJECT_DESTROYED_BLOB ok
ATOMICPROBE_VBLANK_PLACEHOLDER ok
ATOMICPROBE_PASS
```

The probe also checks that the atomic ioctl is refused before
`DRM_CLIENT_CAP_ATOMIC` and that a `TEST_ONLY` commit does not change
`GETCRTC` state.

### Sync objects (`tools/drm/sync_probe.c`)

```
SYNCPROBE_CAP syncobj=1 timeline=1
SYNCPROBE_CREATE plain=1 signaled=2
SYNCPROBE_QUERY initial=0/1
SYNCPROBE_WAIT nonblocking=ok
SYNCPROBE_SIGNAL ok
SYNCPROBE_RESET ok
SYNCPROBE_WAIT_ALL first_signaled=0
SYNCPROBE_TIMELINE point=5
SYNCPROBE_CHILD_PASS
SYNCPROBE_CROSS_PROCESS ok
SYNCPROBE_ERRORS ok
SYNCPROBE_PASS
```

The cross-process case forks: the child blocks on a sync object, the parent
signals it 100 ms later, and the child's wait returns zero.

### RISC-V

The same two probes pass on the RISC-V Sv39 `Image` (QEMU virt,
`-device virtio-gpu-device`), with identical transcripts:

```
PASS (riscv64 atomic_probe)
PASS (riscv64 sync_probe)
```

### Regression: no legacy-path change

- `tools/drm/virtio_gpu_probe.c` (legacy `SETCRTC`/`DIRTYFB`) still passes.
- The x86 Xorg gate (`tools/x86/debian/xorg_check.sh`) still passes:
  `screendump 1024x768 red=1.000`, power-button power-off, clean `e2fsck -fn`.
  Xorg additionally probes two legacy ioctls this core does not implement
  (`MODE_SETPROPERTY` 0xab, `MODE_LIST_LESSEES` 0xc7); it logs one warning per
  probe and continues, which is why they stay out of this block.

## Boundaries of this block

Deliberately left out, each returning a defined error rather than silently
misfiring:

- page-flip events and non-blocking atomic commits (`EINVAL`);
- cursor/overlay planes and multi-CRTC commits (`EINVAL`);
- plane `CRTC_X/Y/W/H` destination rectangles other than the full mode;
- atomic commits without `ACTIVE`, or enabling without `MODE_ID`/`FB_ID`;
- fence import/export for sync objects (`SYNCOBJ_HANDLE_TO_FD`/`FD_TO_HANDLE`);
- vblank waits (`EOPNOTSUPP`) and vblank-based page-flip completion.

The next block (P3 continuation) is the page-flip event queue plus
`DRM_IOCTL_MODE_ATOMIC` with events, which is what makes DRI3 and a compositor
loop feel synchronous; syncobj fence import follows once a dma-fence layer
exists.
