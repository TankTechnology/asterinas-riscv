# Asterinas DRM sysfs 最小节点（B2b/P5b-7，2026-10-24）

## 结论

- Asterinas 现在会为 **firmware framebuffer（simpledrm）后端** 发布最小
  DRM sysfs 视图，此前 `/sys/class` 只有 `graphics`/`tty`，
  `/sys/class/drm` 完全不存在；
- 新增：
  - `/sys/class/drm/card0/dev` = `226:0`
  - `/sys/class/drm/renderD128/dev` = `226:128`
  - 两者各含 `uevent`（MAJOR/MINOR/DEVNAME/DEVTYPE）
  - `/sys/dev/char/226:0`、`/sys/dev/char/226:128` 软链到
    `../../class/drm/{card0,renderD128}`
- ktest `gpu_drm_sysfs_nodes` 通过（`1 passed; 0 failed`）；
- 板级确认 sysfs 节点已被 guest 看到；**EGL 仍未通过**：
  `ASTERINAS_POWERVR_EGL status=failed platform=gbm`，错误从
  `DRI2: failed to create gbm device` 变为更早的
  `eglGetDisplay failed`；说明 sysfs 缺口已补上，下一层阻塞在
  EGL/驱动加载。

## 实现

位置：`kernel/src/device/sysfs.rs`。

- 原先 DRM sysfs 只在
  `driver_name() == DRIVER_NAME`（virtio_gpu）时构建；
  Megrez 的 firmware 后端是 `simpledrm`，因此完全没有 DRM class。
- 新增 `build_firmware_drm_class_node()` 与
  `build_firmware_drm_dev_node()`：
  - `FirmwareDrmMinorSysNode` 只提供 `dev` 与 `uevent` 两个只读属性；
  - `dev` 使用 `crate::device::dri::DRM_MAJOR`（226）与
    `exposed_nodes()` 的 minor（0/128）；
  - `/sys/dev/char` 用相对软链 `../../class/drm/{name}`。
- `build_class_node()` 在 `exposed_nodes()` 非空时：
  - virtio 后端走原有完整 virtio 拓扑；
  - 其它（firmware）后端走新的最小节点。
- `init_in_first_process()` 在 firmware 分支额外挂 `/sys/dev/char`。
- 设备号沿用 `DRM_MAJOR=226`，与现有 DRM 字符设备注册一致，不是
  动态分配。

## P5b-8：`eglGetDisplay failed` 归因

### EGL 库来源

guest 的 EGL vendor 配置只有：

```text
/usr/share/glvnd/egl_vendor.d/50_mesa.json
```

**没有 pvr 的 EGL ICD**（`libEGL_pvr.so` 不存在）；`libEGL_mesa.so.0`
仍是 guest Mesa 25 的 glvnd 选择对象，`/opt/pvr/mesa22/lib` 通过
`LD_LIBRARY_PATH` 提供 Mesa 22 版本。

### 缺库与加载

`libEGL_mesa.so.0`（Mesa 22）的 NEEDED 中，guest 缺少：

```text
libxcb-dri2.so.0
```

已从 RockOS 取来（18,432 B）并注入 `/opt/pvr/mesa22/lib`；其余
`libxcb`/`libX11-xcb`/`libwayland`/`libxshmfence` 等 guest 已有。
补入后 `eglGetDisplay` 之前不再报缺库，但 EGL 仍失败：

```text
eglGetDisplay failed
EGL_RC=1
ASTERINAS_POWERVR_EGL status=failed platform=gbm
```

ctypes 直接调用 `eglGetPlatformDisplay(EGL_PLATFORM_SURFACELESS_MESA,
NULL, NULL)` 返回 **NULL**（DISP None），说明当前 glvnd/Mesa 22 组合
根本没有提供可用的 EGL display；`eglInitialize(NULL, ...)` 返回 0
只是无效 display 的失败路径，不能当作成功。

### 分类

- **a) 目录/文件名**：已排除（`libEGL_mesa.so.0` 和 vendor lib 路径
  都能被解析，缺的 `libxcb-dri2` 已补）；
- **b) Mesa 版本 ABI**：仍然存在（Mesa 22 EGL 与 guest Mesa 25
  glvnd/系统库混用），但目前已先卡在 display/EGL vendor 选择；
- **c) vendor EGL / glvnd 配置**：**当前首要**。guest 只有 Mesa 的
  EGL ICD，没有 PVR 专用 `libEGL_pvr.so` 或 pvr 的
  `egl_vendor.d/*.json`；在这种结构下，即使 `pvr_dri.so` 存在，
  glvnd 也不会把它当成 EGL vendor。

### 建议下一步（P5b-9）

1. 确认 RockOS 是否有 PVR 专用 EGL ICD（`libEGL_pvr.so`/
   `egl_vendor.d`）；若没有，只能用“整套 Mesa 22”替换 guest 的
   glvnd/Mesa，或走 **Mesa 25 重编 pvr_dri**；
2. 若选择整套 Mesa 22：需要同时提供 `libEGL.so.1`（glvnd）、
   `libEGL_mesa.so.0`、`libgbm`、`libglapi`、`libxcb-dri2` 和
   `50_mesa.json` 的隔离路径，避免与 guest Mesa 25 混用；
3. 在 sysfs 已修复的前提下，重跑 `LD_DEBUG=libs` 确认
   `libEGL_mesa.so.0` 和 `pvr_dri.so` 的实际 dlopen 结果，再决定
   是否进入重编。

## P5b-9：照抄 RockOS EGL 配置

### RockOS 侧事实（板子 p3，SSH 读取）

- EGL 库：
  - `/usr/lib/riscv64-linux-gnu/libEGL.so.1.1.0`（glvnd loader）
  - `/usr/lib/riscv64-linux-gnu/libEGL_mesa.so.0.0.0`（Mesa 22 EGL）
  - `/usr/lib/riscv64-linux-gnu/libGLdispatch.so.0.0.0`
  - `/usr/lib/riscv64-linux-gnu/libGLX.so.0.0.0`
- glvnd 配置：只有 `/usr/share/glvnd/egl_vendor.d/50_mesa.json`，
  `library_path = libEGL_mesa.so.0`；**没有 pvr 专用 EGL ICD**；
- `/etc/environment`、`/etc/profile.d/*` 中没有
  `MESA_LOADER_DRIVER_OVERRIDE` / `LIBGL_DRIVERS_PATH`；
  `/etc/ld.so.conf.d` 只有标准 multiarch 路径；
- `pvr_dri.so` 在 `/usr/lib/riscv64-linux-gnu/dri/pvr_dri.so`；
- 结论：**① RockOS 用的是 Mesa `libEGL_mesa`（经 glvnd），不是
  vendor EGL；② 没有 pvr ICD json；③ 没有显式 override/驱动路径，
  RockOS 依赖内核 DRM driver name 为 `pvr`，Mesa loader 因此自然
  加载 `pvr_dri.so`。**

### guest 1:1 复刻

已把 RockOS 的 `libEGL.so.1.1.0`、`libGLdispatch.so.0.0.0`、
`libGLX.so.0.0.0`、`libEGL_mesa.so.0.0.0`、`libglapi`、`libgbm`、
`libLLVM-16`、`libdrm_radeon/nouveau`、`libxcb-dri2` 放入
`/opt/pvr/mesa22/lib`，并用：

```sh
LD_LIBRARY_PATH=/opt/pvr/mesa22/lib:/opt/pvr/lib
LIBGL_DRIVERS_PATH=/opt/pvr/mesa22/lib/dri
MESA_LOADER_DRIVER_OVERRIDE=pvr
EGL_PLATFORM=gbm
```

复跑 `eglconfigs`，结果仍为：

```text
eglGetDisplay failed
EGL_RC=1
ASTERINAS_POWERVR_EGL status=failed platform=gbm
```

补齐 `libxcb-dri2` 与 glvnd 后没有改变失败点。

### 剩余差异（下一步优先）

文件和环境已基本 1:1，最大差异在内核 DRM 的**驱动名字**：

- RockOS `drmGetVersion` 返回 `pvr`，Mesa 自动选择 `pvr_dri.so`，
  libsrv/libpvr_dri_support 也可能按 `pvr` 识别设备；
- Asterinas firmware 后端返回 `simpledrm`（virtio 为 `virtio_gpu`），
  即使设置 `MESA_LOADER_DRIVER_OVERRIDE=pvr`，libsrv 的
  `drmGetDevices2`/`drmGetNodeTypeFromFd` 仍可能按 driver name 拒绝
  设备，导致 `eglGetDisplay` 失败。

因此 P5b-10 的第一件事应是把 PowerVR/firmware 后端的 DRM driver name
变为 `pvr`（或增加可配置的 driver name），然后重跑 EGL；文件/glvnd
复制已不再是主要缺口。

## 边界

- 仅 firmware/simpledrm 后端新增节点；virtio 拓扑保持原样；
- 不声称 EGL 已通过；marker 仍为 `status=failed`。
