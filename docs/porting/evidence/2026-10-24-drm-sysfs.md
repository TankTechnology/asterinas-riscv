# Asterinas DRM sysfs 最小节点（B2b/P5b-7，2026-10-24）

## 结论

- Asterinas 现在会为 **firmware framebuffer（simpledrm）后端** 发布最小
  DRM sysfs 视图，此前 `/sys/class` 只有 `graphics`/`tty`，
  `/sys/class/drm` 完全不存在；
- 新增：
  - `/sys/class/drm/card0/dev` = `226:0`
  - `/sys/class/drm/renderD128/dev` = `226:128`
  - 两者各含 `uevent`（MAJOR/MINOR/DEVNAME/DEVTYPE）
  - `/sys/dev/char/226:0`、`/sys/dev/char/226:128` 软链到
    `../../class/drm/{card0,renderD128}`
- ktest `gpu_drm_sysfs_nodes` 通过（`1 passed; 0 failed`）；
- 板级确认 sysfs 节点已被 guest 看到；**EGL 仍未通过**：
  `ASTERINAS_POWERVR_EGL status=failed platform=gbm`，错误从
  `DRI2: failed to create gbm device` 变为更早的
  `eglGetDisplay failed`；说明 sysfs 缺口已补上，下一层阻塞在
  EGL/驱动加载。

## 实现

位置：`kernel/src/device/sysfs.rs`。

- 原先 DRM sysfs 只在
  `driver_name() == DRIVER_NAME`（virtio_gpu）时构建；
  Megrez 的 firmware 后端是 `simpledrm`，因此完全没有 DRM class。
- 新增 `build_firmware_drm_class_node()` 与
  `build_firmware_drm_dev_node()`：
  - `FirmwareDrmMinorSysNode` 只提供 `dev` 与 `uevent` 两个只读属性；
  - `dev` 使用 `crate::device::dri::DRM_MAJOR`（226）与
    `exposed_nodes()` 的 minor（0/128）；
  - `/sys/dev/char` 用相对软链 `../../class/drm/{name}`。
- `build_class_node()` 在 `exposed_nodes()` 非空时：
  - virtio 后端走原有完整 virtio 拓扑；
  - 其它（firmware）后端走新的最小节点。
- `init_in_first_process()` 在 firmware 分支额外挂 `/sys/dev/char`。
- 设备号沿用 `DRM_MAJOR=226`，与现有 DRM 字符设备注册一致，不是
  动态分配。

| 项 | 值 |
|---|---|
| 内核 | `/tmp/tftp/kernel-pvr-sysfs.Image`，16,726,480 B，CRC32 `54c0168a`，SHA-256 `2bc925786b4d68a6127c1bfe7ddf18c85211cafdc9c075ac9193396a658425d9` |

| 内核 cmdline | `asterinas.powervr=1 ...`（既有参数） |
| guest 工具 | `/opt/pvr`（Mesa22 + vendor DDK，P5b-5 注入） |

板级串口（`target/board-drm-sysfs-20261024/board_sysfs.serial.log`）：

```text
cat /sys/class/drm/card0/dev /sys/class/drm/renderD128/dev
226:0
226:128

ls /sys/dev/char
226:0  226:128
```

随后运行：

```sh
env LD_LIBRARY_PATH=/opt/pvr/mesa22/lib:/opt/pvr/lib \
    LIBGL_DRIVERS_PATH=/opt/pvr/mesa22/lib/dri \
    MESA_LOADER_DRIVER_OVERRIDE=pvr \
    EGL_PLATFORM=gbm timeout 60 /opt/pvr/bin/eglconfigs
```

结果：

```text
eglGetDisplay failed
EGL_RC=1
ASTERINAS_POWERVR_EGL status=failed platform=gbm
```

与 P5b-5 的 `DRI2: failed to create gbm device` 相比，失败点前移到
`eglGetDisplay`，说明 sysfs/DRM 节点这一层已不再直接报 gbm 创建错误；
但 EGL 仍未拿到 display。

## 下一步

1. 在 sysfs 已修复的基础上重跑 `LD_DEBUG=libs,files`，确认
   `pvr_dri.so` 是否终于被 loader 打开；若仍未打开，检查
   `libEGL_mesa.so.0`/glvnd vendor JSON 的加载路径；
2. 若 `pvr_dri` 已被打开但仍失败，记录首个失败符号/EGL 平台错误，
   进入 Mesa 25 重编 pvr_dri 的评估；
3. `gbm` 的 `device`/`subsystem` 软链本次未做（最小集），若
   libdrm 仍需要再加；
4. 不修改 initramfs；本轮只补 sysfs 最小集。

## 边界

- 仅 firmware/simpledrm 后端新增节点；virtio 拓扑保持原样；
- 不声称 EGL 已通过；marker 仍为 `status=failed`。
