# IPv4 interface discovery through `SIOCGIFCONF`

The native LMBench result included `SIOCGIFCONF: Inappropriate ioctl for
device`. The socket file implementation returned `ENOTTY` for every network
interface ioctl. This change implements the read-only IPv4 interface list
request on sockets, using the interfaces visible in the current network
namespace. It follows the native 64-bit Linux `ifconf`/`ifreq` layout and
reports one `sockaddr_in` per configured IPv4 interface. A null result buffer
returns the required byte count; a short buffer receives only whole entries;
an invalid nested result pointer returns `EFAULT`. The pointer and length
contracts follow the [Linux `dev_ifconf` implementation](https://github.com/torvalds/linux/blob/master/net/core/dev_ioctl.c)
and [IPv4 entry writer](https://github.com/torvalds/linux/blob/master/net/ipv4/devinet.c).

The same statically linked RISC-V regression binary, SHA256
`1e97739449bdac5dd5e66baa05908654d4258adcc9aeea6217e7a036e2919758`,
was first run in the disposable Debian QEMU fixture with production kernel
SHA256 `1d59c9ebb44389f3b7d3473bb6db6c8eae5c39f8d28f76336fd4639610284cb0`.
Boot `fcec75c4-9ee3-4c45-b4d4-ccdebab59cd9` returned test status 1:
`SIOCGIFCONF` produced `ENOTTY` instead of an interface list or `EFAULT`.
The [baseline excerpt](2026-09-24-ifconf-baseline.txt) retains the failure.
The test also passed on host Linux before the kernel change.

With the patched release kernel, SHA256
`3d80843d2e412ceecf589477ea5088a36e3434655025f1b962bec09ea075f3cb`,
the same Debian QEMU fixture returned test status 0 in boot
`b6efc8dc-c4be-48ad-ae7a-46ecfe492e96`: all 11 checked behaviors passed.
The C test is part of the normal network regression directory and has its own
short QEMU gate:

```sh
tools/docker/run_dev_container.sh --workspace "$(pwd)" -- \
  make run_kernel AUTO_TEST=ifconf TARGET_ARCH=riscv64 SMP=4 \
  FEATURES=riscv_sv39_mode RELEASE=1
```

That formal gate passed with 10 checks and the unique
`SIOCGIFCONF regression passed.` marker. Its
[complete QEMU log](2026-09-24-ifconf-qemu.log) was checked for the marker and
fatal kernel output by `validate_run_kernel_log.py`. The RISC-V regression
package built with the new C test, and the host validator suite passed 22
tests.

This validates the native 64-bit IPv4 discovery request and its user-buffer
boundaries. The gVisor `SIOCGIFCONF` cases remain blocklisted until run
against this implementation. `/proc/net/dev` and other interface ioctls are
still absent, so this change alone does not establish that all LMBench
hardware/OS metadata warnings disappear. The full native ALL suite was not
repeated for this focused network API change; no physical-board run is claimed.
