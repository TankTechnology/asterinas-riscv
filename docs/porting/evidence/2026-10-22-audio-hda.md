# 音频最小通路：HDA 控制器 + codec + 放音自检

T3 的第一增量。目标是"日常可用"里最直观的缺口：机器能出声。先做方案比较，
再把能落到本仓库环境里的最小通路做到位。

## 为什么是 HDA

| 通路 | 结论 |
|---|---|
| virtio-snd | **本轮不可用**：本机 QEMU 只提供 `vhost-user-snd`（需要外部 vhost-user backend 守护进程，环境里没有），没有 `virtio-snd-pci`。死树里确实有一份 658 行的 virtio-snd 驱动（`kernel/comps/virtio/src/device/sound/`），但没有设备可驱动。 |
| AC97 | **不可用**：QEMU 的 AC97 两条 BAR 都是 I/O port，而本内核 `BarAccess::Io` 仍是 TODO（没有任何 port I/O 支持）。 |
| HDA（`intel-hda`） | **可用**：BAR0 是 MMIO，x86 与 RISC-V virt 都有；QEMU 的 `hda-output` codec 可把采样写进 `-audiodev wav` 文件，天然是可验证的"出声"证据。 |

## 实现（`kernel/comps/audio-hda`）

- PCI 驱动匹配 `8086:2668/27d8/293e`，映射 BAR0，按 HDA 规范复位控制器
  （`GCTL.CRST`），读 `STATESTS` 得到在场 codec。
- 命令通路走 **CORB/RIRB** 环形 DMA（`bus.rs`）：256 项，指针推进后才使用，
  响应通过轮询 `RIRBWP` 收取。
- `codec.rs` 用 `GET_PARAMETER` 枚举 codec：厂商/设备 ID、功能组、widget 表，
  并能查 pin 的连接列表。
- `stream.rs` 是最小放音自检：把第一个 DAC 与输出 pin 配成 48 kHz/16-bit/立体声，
  一段 DMA 缓冲 + 一条 BDL 描述符 + 一个流描述符，播放 0.5 秒 440 Hz 方波。
  自检默认关闭，只有内核命令行带 `aster_audio.selftest` 时执行（桌面启动保持安静）。

调试过程中确认的 QEMU/规范细节（都已固化在代码注释里）：

1. CORB 与 RIRB 的读写指针都是"先推进再使用"：复位后第一条命令写在槽位 1，
   QEMU 读的是 `corb_rp + 1`；响应同样写到 `rirb_wp + 1`。
2. `RINTCNT` 到点后控制器会停下来等中断确认；驱动用 `RINTCNT=0xFF` 并每收一条
   响应清一次 `RIRBSTS`，保持只轮询、不接中断。
3. 流描述符的 `SRST` 不会自清：写 1 复位、再写 0 释放，不能等它自己变 0。
4. QEMU 的模型把描述符 0–3 当采集、4–7 当播放：输出流必须用索引 ≥ 4，
   否则 codec 侧永远不会启动（LPIB 停在 0、宿主 WAV 不增长）。
5. 完成判据用 `SD_STS.BCIS`，因为 `LPIB` 到缓冲区末尾会绕回 0。

## 验收

```
$ make test_x86_audio
capture peak=8000 sign_changes=835
PASS (HDA playback: controller, codec 2/3, 48 kHz stereo tone captured)
```

门禁（`tools/audio/hda_check.sh`）的判据全部来自宿主侧的真实音频文件：

- 内核日志出现 `stream: played 96000 bytes on dac 2 pin 3` 与
  `self-test tone finished: 96000 bytes`；
- QEMU `-audiodev wav` 捕获到的 44 字节头之后有 PCM；
- 第一秒采样峰值恰为 8000（自检幅度），过零次数 835 ≈ 2×440（440 Hz 方波）。

codec 身份：`vendor=0x1af40012 device=0x1af40012 revision=0x00100101`，
widget 表 `2:0 3:4`（节点 2 是 DAC，节点 3 是输出 pin）。

## 卡点与替代路径（"aplay 在真机出声"）

本环境**没有真机**，也还没有 ALSA 用户态接口：驱动目前是内核自检，没有
`/dev/snd/controlC0`、`/dev/snd/pcmC0D0p`，因此 Debian 镜像里的 `aplay`
无从打开设备。按规则记两条替代路径：

1. **补齐 ALSA PCM 最小 UAPI**（推荐下一步）：注册 `/dev/snd/controlC0` 与
   `pcmC0D0p`，实现 `SNDRV_PCM_IOCTL_INFO/HW_PARAMS/PREPARE/WRITE/START/DRAIN`
   与 `SNDRV_CTL_IOCTL_CARD_INFO` 的最小子集，把 `stream.rs` 的缓冲接到
   `write()`；随后在 Debian 镜像里用 `aplay` 验证。工作量约与 `drm` 的 ioctl
   面相当，但接口语义明确。
2. **换 virtio-snd**：把死树的 `device/sound` 移植到活树，并用带
   `virtio-snd-pci` 的 QEMU（或给 `vhost-user-snd` 配 `vhost-device-sound`
   守护进程）。协议比 HDA 简单，但依赖 QEMU/backend 版本，且当前构建两者都没有。

真机验证还需要 codec quirk 表（不同主板的 pin/amp 配置），这一点在本轮无法
覆盖；内核侧通路（命令环、流描述符、DMA）已经是架构中立的，RISC-V 上只需
确认 PCIe 枚举（本轮未跑）。

## 边界

- 只有一条播放流、固定 48 kHz/16-bit/立体声；没有 44.1 kHz、没有录音、没有音量控制。
- 中断未启用，完成靠轮询；桌面负载下应改为 IOE 中断 + 唤醒等待者。
- 没有 ALSA 节点，`aplay` 尚不可用（见上）。
- 自检是 opt-in 的内核行为，不是用户态写音频。
