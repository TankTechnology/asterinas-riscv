# Fences, sync-file export/import, and explicit fencing (P3-1b)

Continues P3 after
[`2026-10-22-x86-flip-vblank.md`](2026-10-22-x86-flip-vblank.md). The goal's
fence requirement now holds: a sync object can be exported as a sync-file
descriptor, imported in another process, and page-flip/atomic commits accept
in/out fences.

## Kernel

- `kernel/comps/drm/src/fence.rs`: `DrmFence`, a minimal dma-fence
  equivalent. Signal state and timeline point are IRQ-safe (SpinLock), waits
  use `aster_core::wait_until_or_timeout`, and listeners let sync-file
  descriptors wake `poll` when the fence changes.
- `syncobj.rs` is now fence-backed: a sync object holds a `DrmFence` plus a
  timeline/binary view. Exporting shares the fence; importing wraps the
  imported fence.
- `kernel/comps/drm/src/sync_file.rs`: `anon_inode:[drm-sync-file]`
  descriptors. `poll` reports `IN` once the fence reaches the descriptor's
  point, and `read`/`write`/`mmap` are refused as on Linux.
- `SYNCOBJ_HANDLE_TO_FD` (0xc1) / `SYNCOBJ_FD_TO_HANDLE` (0xc2) with the
  `SYNC_FILE` and `TIMELINE` flags. Other export forms return `EOPNOTSUPP`.
- Atomic KMS gains the standard `IN_FENCE_FD` (plane) and `OUT_FENCE_PTR`
  (CRTC) properties. A commit with an in-fence waits for it and consumes the
  descriptor (`aster_core::fs::file::close_file_fd`); an out-fence pointer
  receives a signaled sync-file fd, because this driver completes commits
  synchronously.

## Acceptance

`tools/drm/sync_probe.c` now also checks export, import, polling the
descriptor, signalling through the exporting handle and waiting through the
imported handle, and a cross-process handshake where the child imports the
descriptor and the parent signals it:

```
SYNCPROBE_FENCE_EXPORT ok
SYNCPROBE_FENCE_CHILD_PASS
SYNCPROBE_FENCE_CROSS_PROCESS ok
SYNCPROBE_FENCE_ERRORS ok
```

`tools/drm/atomic_probe.c` exports a signaled sync object as a sync-file,
arms it through the plane's `IN_FENCE_FD` property and reads the CRTC's
`OUT_FENCE_PTR` back:

```
ATOMICPROBE_IN_FENCE fd=4
ATOMICPROBE_IN_FENCE_CONSUMED ok slot_reused=1
ATOMICPROBE_OUT_FENCE fd=4
```

`IN_FENCE_CONSUMED` checks that the commit closed the descriptor the way
Linux does; `slot_reused=1` means the kernel's out-fence then took the freed
slot, which is exactly what a consumed descriptor looks like when the
descriptor numbers are reused. The out-fence is polled for `POLLIN` before
the probe accepts it.

Both probes run on x86_64 and RISC-V with identical transcripts, from the same
`IN_FENCE_FD`/`OUT_FENCE_PTR` properties and the same sync-file code:

```
$ tools/drm/initramfs_probe_check.sh --arch amd64 --kernel target/prime/kernels/x86.elf \
    --probe tools/drm/sync_probe.c --pass SYNCPROBE_PASS ...
SYNCPROBE_FENCE_EXPORT ok
SYNCPROBE_FENCE_CHILD_PASS
SYNCPROBE_FENCE_CROSS_PROCESS ok
SYNCPROBE_FENCE_ERRORS ok
SYNCPROBE_PASS

$ tools/drm/initramfs_probe_check.sh --arch riscv64 --kernel target/prime/kernels/riscv.Image \
    --probe tools/drm/atomic_probe.c --pass ATOMICPROBE_PASS ...
ATOMICPROBE_IN_FENCE fd=4
ATOMICPROBE_IN_FENCE_CONSUMED ok slot_reused=1
ATOMICPROBE_OUT_FENCE fd=4
ATOMICPROBE_PASS
``` The legacy
KMS probe, flip probe and the x86 Xorg gate
(`screendump 1024x768 red=1.000`, power-off, clean `e2fsck -fn`) still pass.

## Reproduction

```sh
cargo osdk build --target-arch x86_64 --boot-method vmm-direct
cp target/osdk/asterinas/asterinas-osdk-bin.elf target/prime/kernels/x86.elf
make test_x86_syncobj
make test_x86_atomic
```

## Boundaries

- Import shares the exporter's fence: signalling through an imported handle
  also signals the exporter. Linux copies the fence instead; waits (the
  useful direction) behave the same.
- Only sync-file export/import is implemented; `SYNCOBJ_TRANSFER`,
  `SYNCOBJ_EVENTFD` and fd-based syncobj handles return `EOPNOTSUPP`.
- The out-fence of a commit is already signaled when userspace receives it,
  because the commit completes inside the ioctl. It still exercises the
  userspace protocol (fd ownership, `poll`, wait).
- Legacy `MODE_PAGE_FLIP` has no fence fields in the UAPI; explicit fencing
  is atomic-only.
- Cross-device fences remain out of scope (no dma-buf attachment layer).
