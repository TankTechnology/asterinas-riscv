# M8 Report: NixOS stage-2 feasibility — two-route go/no-go

> 2026-08-14. Follow-up to `M7-report.md`. Goal (issue #24): evaluate the two
> routes to a bootable Nix-managed system on Asterinas RISC-V and produce a
> go/no-go recommendation.
>
> **Route A (lightweight)** — busybox-init + nix-profile activation
> (Alpine-style): boot directly into the initramfs rootfs, activate a nix
> profile, run profile-installed binaries from a login shell. **No systemd, no
> switch_root.**
>
> **Route B (full)** — systemd stage-2: full NixOS with systemd as PID 1.

## Conclusion up front

**Route A is GO — and is already demonstrated working in this repo.** A new
`/init` boots the M7 rootfs, `nix profile install`s a hello derivation into
`/nix/var/nix/profiles/default` in **single-user mode (no daemon, no systemd)**,
then runs a login shell that sources `/etc/profile` (which puts the profile's
`bin` on `PATH`) and executes the installed binary by bare name. The whole
sequence completes in ~25 s in QEMU. It needs **no kernel change** and none of
the stage-1 machinery (pivot_root / switch_root / cgroup / mount propagation)
that a full NixOS needs.

**Route B is NO-GO for now**, but not because of any single killer kernel gap.
Three independent reasons stack up:

1. **Build burden.** There is no prebuilt riscv64 NixOS system closure (systemd
   + nixpkgs base). The upstream Asterinas NixOS (`distro/`) is x86_64-only and
   relies on a populated cache. On riscv64 a full NixOS must be cross-compiled
   from scratch.
2. **The `ET_EXEC` + `PT_INTERP` ELF-loader bug** (M6-report.md) blocks `gcc`/
   `cc1`, so the toolchain cannot run in-guest; any source build must happen on
   the host or via a cross-toolchain.
3. **Three+ kernel gaps** must be patched first (pivot_root from the initramfs
   root, mount propagation `MS_SLAVE`, `/proc/self/mountinfo` completeness —
   the exact three things upstream patched in its systemd overlay), plus a
   handful of missing syscalls (`openat2`, `fanotify`, `keyctl`,
   `mount_setattr`, `membarrier`, `seccomp`).

The kernel capability matrix below shows the lightweight route's requirements
are **all already met**, while the full route's are only partially met and are
each individually mitigable but jointly expensive.

## 1. Scope and method

The plan (issue #24) asks for five steps: (1) inventory NixOS stage-2
activation dependencies; (2) verify each kernel capability in QEMU with a
small repro; (3) prototype the lightweight route; (4) estimate the systemd
route workload; (5) write this report.

The authoritative reference for *both* routes already exists in-tree:
`distro/` is upstream Asterinas's **x86_64 NixOS distribution**. It contains a
minimal stage-1 (`distro/etc_nixos/modules/core.nix`, a `switch_root`-based
shell script), a **patched systemd** (`distro/etc_nixos/overlays/systemd/`),
a D-Bus bypass (`distro/etc_nixos/overlays/switch-to-configuration-ng/`), and —
critically — a `disable-systemd = "true"` mode whose stage-2 fallback is the
literal command **`/bin/sh -l`** (a login shell). Route A of this milestone is
exactly that fallback, re-expressed for riscv64. Route B is the x86_64 systemd
path ported to riscv64.

Step (2) is performed by a standalone static `/init` (`cap_repro.c`) run in
QEMU; its per-item results are in §3.

## 2. NixOS stage-2 activation dependency inventory

NixOS's boot has two phases, each with a distinct kernel dependency set.

### 2.1 Stage-1 (initramfs → real root)

Upstream's `core.nix` stage-1 is deliberately minimal and already shows what a
*working* Asterinas NixOS needs:

```sh
mkdir /sysroot
mount -t ext2 "$NEW_ROOT" /sysroot     # the real root FS
mount -t proc none /sysroot/proc
mount --move /dev /sysroot/dev          # carry device nodes across
exec switch_root /sysroot "$NEW_INIT" "$ARGS"
```

The `switch_root` applet (busybox) is **chroot-based**, not pivot_root-based:
it moves the mounts into the new root, `chroot`s, deletes the old initramfs,
and `exec`s the new init. Its kernel requirements are therefore:

| Capability | Why stage-1 needs it |
|---|---|
| `mount` of `ext2` (+ `tmpfs`, `proc`, `sysfs`) | root FS + pseudo-FS |
| `mount --move` (`MS_MOVE`) | carry `/dev` into `/sysroot/dev` |
| **`chroot`** | the actual `switch_root` switch |
| device nodes in `/dev` (console, null, …) | stdio + terminal |
| (`pivot_root` — *not* used by `switch_root`) | only if a custom init pivots directly |

### 2.2 Stage-2 (activation script + PID 1)

The NixOS activation script (generated by `switch-to-configuration.pl` /
`activate`), run after `switch_root`, does:

| Step | Kernel / system dependency |
|---|---|
| populate `/etc` (symlinks into `/nix/store`) | symlink + read-only store |
| build `/run/current-system/sw` profile | symlinks, `rename` |
| create users/groups (`users-groups.pl`) | `getpwnam`/`getgrnam`, `chown`, `setuid` |
| set hostname / machine-id / timezone | `sethostname`, `/etc` writes |
| `systemctl daemon-reload` + unit activation | **systemd** (Route B) |
| run `systemctl start …` / `switch-to-configuration` | systemd + D-Bus (Route B) |

For Route A, only the top four rows apply — and none of them needs systemd or
D-Bus; they are plain file/credential operations, all of which M3–M7 already
exercised.

## 3. Kernel capability verification (QEMU)

`cap_repro.c` (built by `build_m8_cap.sh`, driven by `boot_m8_cap_smoke.py`)
runs eight probes in the guest and prints one marker each. Full run:

```
=== M8 capability repro results ===
  T1 /dev nodes: OK                # null/zero/console/ttyS0 are char devices
  T2 devtmpfs fstype absent: OK    # mount("devtmpfs") -> ENODEV (not registered)
  T3 /proc/self: OK                # readlink -> "1" (M1 gap now fixed)
  T4 unshare CLONE_NEWNS: OK
  T4 mount in child: OK
  T4 namespace isolated: OK
  T5 pivot_root EINVAL (gap): OK
  T6 cgroup2 mount: OK
  T6 controllers listed: OK        # "cpuset cpu memory pids"
  T6 subtree_control write: OK     # "+cpu +memory +pids"
  T6 child controllers: OK         # child sees "cpu memory pids"
  T7 MS_SLAVE unsupported: OK      # EINVAL
  T7 MS_PRIVATE ok: OK
  T8 chroot: OK
  T8 chroot root active: OK
```

### 3.1 Verified working (Route A needs only these)

| Capability | Evidence |
|---|---|
| `/dev` device nodes (`null`/`zero`/`console`/`ttyS0`) | char devices with major:minor (created by the device registry, not a mount) |
| mount namespace `CLONE_NEWNS` + `unshare` | child's tmpfs mount invisible to parent |
| `chroot` | `chroot("/chr")` then `/CHROOT_MARKER` visible at new root |
| cgroup v2 | mount `cgroup2`, read `cgroup.controllers`, `mkdir` sub-cgroup, write `cgroup.subtree_control`, child gets `cpu memory pids` |
| `/proc/self` magic symlink | `readlink → 1` — resolves the M1 gap |

### 3.2 Verified gaps (Route B must mitigate these)

| Capability | Result | Mitigation (upstream) |
|---|---|---|
| **`pivot_root`** | `EINVAL` — kernel rejects it when the *current* root is the initramfs rootfs (requires the root to be a non-rootfs mount; `resolver.rs` checks `root.mount.parent().is_none()`) | NixOS stage-1 uses `switch_root` (`chroot`), which **works** (T8) |
| **`devtmpfs` fstype** | `ENODEV` — not a registered fstype; device nodes exist only via the registry | device nodes are already present; skip the mount |
| **mount propagation `MS_SLAVE`/`MS_SHARED`** | `EINVAL`; only `MS_PRIVATE` works | upstream systemd patch 0003 (`MS_SLAVE`→`MS_PRIVATE`) |

The `pivot_root` EINVAL is the one genuinely new finding: `sys_pivot_root` is
wired into the syscall table but returns `EINVAL` from the initramfs root, so a
naive `pivot_root`-based init would fail. Because NixOS's own stage-1 uses
`switch_root` (chroot), this is a documented gap rather than a blocker.

## 4. Lightweight route prototype (Route A)

`init_m8_light.c` + `build_m8_light.sh` + `boot_m8_light_smoke.py` layer the
Alpine-style activation on top of the M7 rootfs:

1. mount `proc`/`sys`/`tmp`, prepare `/nix`;
2. **single-user** `nix profile install --profile /nix/var/nix/profiles/default --impure --expr 'import /m8/hello.nix'`
   (no daemon — the genuinely lightweight config, `build-users-group = ` in
   `nix.conf`);
3. verify `/nix/var/nix/profiles/default/bin/hello` exists;
4. `exec /bin/sh -l -c 'command -v hello && hello'` — the login shell sources
   `/etc/profile` (which prepends the profile `bin` to `PATH`) and runs the
   installed binary by bare name.

`/etc/profile` is the entire "activation":

```sh
export PATH="/nix/var/nix/profiles/default/bin:/root/.nix-profile/bin:$PATH"
```

### Results

```
=== M8 lightweight smoke results ===
  nix profile install exit 0:     OK    __M8_INSTALL_EXIT__=0
  profile bin/hello present:      OK    __M8_PROFILE_BIN__=OK
  profile sourced (login shell):  OK    __M8_PROFILE_SOURCED__
  login shell PATH has profile:   OK    __M8_PATH__=/nix/var/nix/profiles/default/bin:…
  hello resolved from profile:    OK    __M8_HELLO__=Hello, world!
```

The whole boot→install→login→run sequence completes in **~25 s** in QEMU.

### Finding: daemon-mode `nix profile install` hangs; single-user works

The first cut of this milestone ran `nix profile install` through the
`nix-daemon` (the M7 multi-user layout). That build did **not** complete in
240 s — the daemon accepted the client connection and looped on `openat`/
`read`/`fcntl` without ever forking a builder. Switching to single-user mode
(no daemon) completed the same install in ~25 s. The root cause is not yet
isolated (the daemon itself is sound — M7 drove three builds through it); it is
specific to the `nix profile` code path under daemon mode. This is a nix
client-side behaviour, not a kernel gap, and it *reinforces* the lightweight
choice: no daemon is both faster and simpler. (Documented here, not fixed, as
it does not block the route.)

## 5. Systemd route workload (Route B)

The workload is best read from the upstream x86_64 reference, which already
made systemd boot on Asterinas. It needed **three source patches**, a **D-Bus
bypass**, and **ten services disabled/stubbed**.

### 5.1 systemd source patches (from `distro/etc_nixos/overlays/systemd/`)

| Patch | Kernel gap it papers over |
|---|---|
| `0001-Skip-mount-state-checking` | `/proc/self/mountinfo` not complete enough for systemd's mount-state verification |
| `0002-Disable-loop-too-fast-warning` | (cosmetic; timers/logging) |
| `0003-Switch-MS_SLAVE-to-MS_PRIVATE` | no `MS_SLAVE`/`MS_SHARED` mount propagation |

### 5.2 Services disabled / stubbed (from `systemd.nix` + the systemd overlay)

`systemd-coredump`, `systemd-oomd`, `logrotate`, `network-setup`, `resolvconf`,
`systemd-random-seed`, `systemd-tmpfiles-{setup,clean}`, `timesyncd`, **`udev`**
all disabled; `systemd-logind`, `systemd-user-sessions`, `user@`,
`user-runtime-dir@`, `firstboot`, `dbus-org.freedesktop.login1` stubbed to
`/bin/true`. `switch-to-configuration-ng` is patched to bypass D-Bus.

### 5.3 Missing syscalls (verified absent from the riscv64 syscall table)

| Syscall | systemd use | Severity |
|---|---|---|
| `openat2` | `O_RESOLVE`-style opens | low (graceful fallback to `openat`) |
| `mount_setattr` | mount-tree tweaks (`systemd-mount`) | low–med |
| `fanotify_init` | `systemd-journald`/tmpfiles watch | med (journald degrades) |
| `keyctl`/`add_key` | kernel keyring (credentials) | low (degrades) |
| `membarrier` | threading (libc) | none (ENOSYS, inherited) |
| `seccomp` | `SystemCallFilter=`, sandboxing | med (returns EINVAL; nix already bypasses with `filter-syscalls=false`) |
| `landlock` | sandboxing | none (ENOSYS probe) |

None is individually a boot blocker — systemd is written to degrade — but each
adds noise and reduces functionality (no journald file watches, no sandboxing,
no keyring-backed credentials, no mount namespace hardening).

### 5.4 riscv64-specific build cost

The decisive cost is not kernel, it is **build**: a riscv64 NixOS system
closure (systemd + glibc/musl + the nixpkgs stdenv + ~hundreds of packages)
does not exist prebuilt, so it must be cross-compiled. And the `ET_EXEC`+
`PT_INTERP` loader bug (M6) blocks running `gcc`/`cc1` in-guest, forcing all
builds to the host. Upstream did this on x86_64 where a cache existed; on
riscv64 there is no such cache.

## 6. Comparison, gap list, recommendation

| Dimension | Route A (lightweight) | Route B (systemd) |
|---|---|---|
| Kernel gaps to close | **none** (all verified in §3.1) | pivot_root-from-initramfs, `MS_SLAVE`, mountinfo, + syscalls in §5.3 |
| systemd/D-Bus/udev | not needed | required (3 patches + 10 disabled services) |
| Build cost | reuse M7 rootfs (36 MB) | full riscv64 NixOS cross-compile (no cache) |
| `ET_EXEC` loader bug | does not block | blocks in-guest gcc |
| Status | **demonstrated working** | not attempted (est. multi-week) |
| Delivers "Nix-managed system" | ✅ profile-installed binaries run | ✅ (richer: services, units) |

### Remaining gap list (all routes)

| Gap | Impact | Route |
|---|---|---|
| `pivot_root` from initramfs root → EINVAL | custom pivot-based init fails; NixOS uses chroot | B |
| `MS_SLAVE`/`MS_SHARED` mount propagation | systemd must be patched to `MS_PRIVATE` | B |
| `devtmpfs` not a mountable fstype | `mount -t devtmpfs` fails; nodes already exist | B (minor) |
| `openat2`/`fanotify`/`keyctl`/`mount_setattr` absent | degraded systemd features | B |
| `seccomp` BPF unimplemented | no builder/service sandboxing | both (nix bypasses) |
| `ET_EXEC`+`PT_INTERP` loader bug | blocks non-PIE dynamic binaries (`gcc`) | B (blocks in-guest build) |
| virtio-blk SMP race (`-smp 4` hangs ~2/3 boots) | forces `-smp 1` | both (perf only) |

### Recommendation

**Go on Route A (lightweight).** It is already working end-to-end in this repo
with zero kernel changes, satisfies the milestone's acceptance criterion
("boot into a Nix-managed system that runs profile-installed binaries"), and is
the natural incremental next step after M7. Recommended follow-ons, in order:
(1) make the login shell the persistent PID-1 child (a real getty/login
loop) instead of a one-shot `sh -l -c`; (2) `nix profile install` a second
package to prove profile *generations* and updates; (3) drive it with `-smp 4`
once the virtio-blk race is fixed.

**No-go on Route B (full systemd) for now**, and *not* because of any single
kernel gap: the three kernel gaps are individually patchable (upstream already
has the patches), but the absence of a riscv64 NixOS cache plus the `ET_EXEC`
loader bug make the build alone a multi-week effort with uncertain payoff
relative to the lightweight route. Re-evaluate Route B once (a) the `ET_EXEC`
loader bug is fixed in the sibling `asterinas-riscv` tree, and (b) a riscv64
NixOS bootstrap cache is available.
