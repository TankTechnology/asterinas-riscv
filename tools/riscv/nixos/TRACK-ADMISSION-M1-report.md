### Admitted M7 source fixture

`tools/riscv/nixos/m7/scm_repro.c` is adapted and admitted from
`8a7396a1fae4dfce21b2d0e19794b83dd7771bd8` as a source-only fixture for #67.
Its focused test checks the SPDX marker, provenance, SCM_RIGHTS and
SO_PEERCRED on a server-accepted connection from a distinct child, checkout
independence, warning-free host compilation, and timeout-bounded host
execution.
Default execution restricts its credential-status marker to the PID-only
`__M7_PEERCRED_PID_OK__ ... distinct_ids=0`;
it still emits lifecycle and SCM-transfer markers,
and it does not claim UID/GID isolation.
Full credential validation requires root execution of
`"$repro_bin" --require-distinct-ids` from the README's private temporary
directory recipe.
The child then drops to 65534:65534 before connecting,
and the parent requires
`__M7_PEERCRED_OK__ ... uid=65534 gid=65534 distinct_ids=1`.
The fixture uses a Linux abstract AF_UNIX address,
so it creates no persistent socket path.
Abstract bind collisions retry a bounded `(parent PID, attempt)` name sequence.
A single five-second monotonic deadline covers accept, SCM receive readiness,
and child exit. Cleanup checks the `SIGKILL` result and uses WNOHANG under a
250 ms deadline; `PR_SET_PDEATHSIG(SIGKILL)` independently bounds the child
lifetime when a credential-dropped child cannot be signalled by the parent.
Thus pre-connect exit, post-connect send stall, and cleanup `EPERM` cannot
enter an unbounded wait.
These are host checks and an Asterinas/QEMU acceptance recipe, not an
Asterinas/QEMU runtime PASS.
The old rootfs builder, cached closure, boot integration, and historical PASS
claim from that commit are not admitted.

Additional portable inputs are the ET_EXEC reproducer (`4e9550e11...`),
focused mount/security/seccomp smoke sources (`e3fd90d80...`, `b5f0cfca6...`,
`48666769a...`, `549b70f52...`, `1f284a1c1...`), audio tests/design
(`ee05b6db7...`, `9ee857424...`, `b95fe9745...`), the file-handle
reproducer (`60fdb6734...`), raw sched/fork probes (`61edb1bca...`), and the
BusyBox scaffold (`b1d26f029...`). BusyBox, Alpine, placeholders, and sibling
track artifacts are scaffolding only; none is a full NixOS closure.

## Regeneration and local verification

Run locally from the repository root. No remote CI wait or monitoring is part
of this milestone.

The checked-in snapshot is the input used by the hermetic manifest-completeness
test. It records the exact output for the fixed base and track SHAs above, so
that test does not require either historical Git object. The separate live
integration test compares a locally available history with the snapshot.

When the fixed history is deliberately refreshed, first verify both commits,
replace the snapshot from the live refs, and then update the generated
manifest:

```bash
git rev-parse --verify b54aad2f89ce529691dd9944dac53bf33c8dcb93^{commit}
git rev-parse --verify 44172c41cb914e510ec45fb8b65441b0fafa4c6b^{commit}
git cherry -v \
  b54aad2f89ce529691dd9944dac53bf33c8dcb93 \
  44172c41cb914e510ec45fb8b65441b0fafa4c6b \
  > tools/riscv/nixos/track-admission-git-cherry.v1.txt
python3 tools/riscv/nixos_track_audit.py \
  --base b54aad2f89ce529691dd9944dac53bf33c8dcb93 \
  --track 44172c41cb914e510ec45fb8b65441b0fafa4c6b \
  --overrides tools/riscv/nixos/track-admission-overrides.v1.json \
  --output tools/riscv/nixos/track-admission.v1.json
```

Acceptance verification must not overwrite the checked-in generated file. It
uses one automatically cleaned temporary directory for the candidate manifest
and all Python cache output. The explicit `cmp` against a new live
`git cherry` output is the snapshot freshness check:

```bash
verify_tmp="$(mktemp -d)"
trap 'rm -rf "$verify_tmp"' EXIT
export PYTHONPYCACHEPREFIX="$verify_tmp/pycache"

git cherry -v \
  b54aad2f89ce529691dd9944dac53bf33c8dcb93 \
  44172c41cb914e510ec45fb8b65441b0fafa4c6b \
  > "$verify_tmp/track-admission-git-cherry.v1.txt"
cmp tools/riscv/nixos/track-admission-git-cherry.v1.txt \
  "$verify_tmp/track-admission-git-cherry.v1.txt"

python3 tools/riscv/nixos_track_audit.py \
  --base b54aad2f89ce529691dd9944dac53bf33c8dcb93 \
  --track 44172c41cb914e510ec45fb8b65441b0fafa4c6b \
  --overrides tools/riscv/nixos/track-admission-overrides.v1.json \
  --output "$verify_tmp/track-admission.v1.json"
cmp tools/riscv/nixos/track-admission.v1.json \
  "$verify_tmp/track-admission.v1.json"

python3 -m unittest tools.riscv.tests.test_nixos_track_audit
python3 -m py_compile tools/riscv/nixos_track_audit.py \
  tools/riscv/tests/test_nixos_track_audit.py

jq -e '
  (.records | length == 108)
  and (.counts | has("unclassified") | not)
  and ((.counts | to_entries | map(.value) | add) == 108)
  and ([.records[] |
    select(any(
      .source_commit, .subject, .classification, .reason, .destination,

git diff --check origin/main...HEAD
```

In a shallow or object-filtered checkout, the hermetic completeness test still
uses the checked-in snapshot. The live integration test skips cleanly when
either pinned commit is absent. Fetch enough history to make both commits and
their intervening ancestry available (or unshallow the checkout) before using
the refresh or live-check commands; a fixture change without that live
comparison is not accepted.

Every uncertainty or required retest is routed to an explicit issue/PR. Old
screenshots, reports, and branch-local runs remain historical until that
destination produces focused current-main evidence.
